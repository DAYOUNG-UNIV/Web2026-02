# checklist.md — 제대로 되었나

이 문서는 10주차에 씁니다. `docs/requirements.md`의 사용 장면 단계마다 한 줄, 알파 '확인할 것' 한 줄, 공통 항목을 적습니다.
PR을 올리기 전에 해당 줄을 직접 확인하고 체크합니다. AI 에이전트에게도 "끝났다고 말하기 전에 이 파일을 확인하라"고 합니다.

## 쓰는 법

- 한 줄 = 눈으로 확인할 수 있는 한 문장. "잘 된다", "문제없다"는 쓰지 않습니다.
- 한 줄에 조건 하나. "A가 보이고 B가 저장된다"는 두 줄로 나눕니다.
- 체크는 확인한 사람이 합니다. AI가 "확인했다"고 말한 것은 체크하지 않습니다.
- 12주차부터 이 줄들을 자동 테스트로 옮깁니다. 아래 '테스트로 옮기기'를 봅니다.

## 공통

- [ ] 새 폴더에 clone해서 README의 실행 방법대로 하면 실행된다.
- [ ] 코드·커밋·`.env`에 키나 비밀이 없다. `.gitignore`에 `.env`, `node_modules`가 있다.
- [ ] 키보드만으로(Tab, Enter, Esc) 사용 장면을 처음부터 끝까지 간다. 포커스가 어디 있는지 보인다.
- [ ] 빈 상태(데이터 없음), 오류 상태(가져오기 실패), 로딩 상태가 각각 화면에 보인다.
- [ ] 모바일 폭(360px)에서 가로 스크롤이 없고 글자가 잘리지 않는다.
- [ ] README의 실행 방법이 실제와 맞다(명령·포트·폴더 이름).
- [ ] 브라우저 콘솔에 빨간 오류가 없다.
- [ ] 이미지에 alt가 있고, 입력창에 label이 있고, 버튼은 button 요소다.

## 테스트로 옮기기 (12주차)

체크 한 줄은 자동 테스트 하나가 될 수 있습니다. 순수 함수(입력 → 출력)부터 옮깁니다.

<details>
<summary>예시 · 메모 분류</summary>

| 체크 줄 | 테스트 (Vitest) |
|---|---|
| '나누기'를 누르면 카드가 3개 이상 보인다 | `splitNotes("…")`의 결과 길이가 3 이상 |
| 빈 입력이면 안내가 보인다 | `splitNotes("")`가 빈 배열을 돌려준다 |
| 새로고침해도 옮긴 결과가 남아 있다 | `save(state)` 뒤 `load()`가 같은 배열을 돌려준다 |

```js
// test/split.test.js
import { test, expect } from "vitest";
import { splitNotes } from "../src/split.js";

test("빈 입력이면 빈 배열", () => {
  expect(splitNotes("")).toEqual([]);
});
```

실행: `npm i -D vitest` 한 번, 그 뒤 `npx vitest run`.
통과하는 테스트가 곧 맞는 테스트는 아닙니다. 구현을 그대로 베낀 테스트는 버그를 못 잡습니다.

</details>
