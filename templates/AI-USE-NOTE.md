# AI USE NOTE

AI 사용도 작업 과정의 일부입니다. 모든 프롬프트를 제출할 필요는 없습니다. 결과물에 실질적인 영향을 준 AI 활용을 짧게 기록합니다.
AI 사용량은 평가 기준이 아닙니다. 이해·판단·검증·수정이 핵심입니다. 설명할 수 없는 코드, 검토 없는 제출, 출처 미기재는 감점입니다.

## 양식

네 칸을 채웁니다. 한 칸에 한두 문장이면 충분합니다.

| 칸 | 질문 | 적을 것 |
|---|---|---|
| 어떤 도구 | 어떤 도구를 사용했는가? | ChatGPT Edu, 에이전트(Codex 또는 Claude Code), 그 밖의 도구. 쓰지 않았으면 "없음" |
| 어떤 작업을 맡겼나 | 어떤 작업을 맡겼는가? | 초안·설명·오류 찾기·리뷰·반복 작업 중 무엇. 요청 문장을 한 줄로 |
| 무엇을 판단했나 | 무엇을 판단했는가? | 받아들인 것과 거절한 것, 그 이유. 바꾼 부분 |
| 어떻게 검증했나 | 어떻게 검증했는가? | 직접 실행·눌러 봄·Network 탭·테스트·다른 사람 리뷰 중 무엇 |

복사용:

```
AI USE NOTE
- 어떤 도구:
- 어떤 작업을 맡겼나:
- 무엇을 판단했나:
- 어떻게 검증했나:
```

PR 본문에는 한 줄로 줄여 씁니다. `AI USE NOTE: 도구 / 맡긴 작업 / 판단 / 검증`

## 어디에 적나

| 어디 | 언제 | 길이 |
|---|---|---|
| PR 본문 | PR마다 | 한 줄 |
| README의 AI USE NOTE 표 | 팀 제출마다 | 팀 전체에서 영향이 큰 것 2~5개 |
| docs/portfolio-*.md | 15주차 개인 | 한 학기 모음 |

## 예시 1 · 팀 PR (11주차, 에이전트)

```
AI USE NOTE
- 어떤 도구: 에이전트(Codex). 요청은 ChatGPT Edu로 먼저 다듬음.
- 어떤 작업을 맡겼나: "data/friend.json을 fetch로 읽어 오른쪽 열에 그려 줘. 로딩·빈·오류 상태를 각각 표시하고, 새 라이브러리는 쓰지 마. 바꾼 파일과 이유를 먼저 설명해."
- 무엇을 판단했나: 로딩 표시를 위해 spinner 라이브러리를 제안했지만 거절하고 "불러오는 중…" 글자로 바꿈. 오류 상태에서 response.ok를 확인하지 않아 404가 성공으로 보이던 부분을 직접 고침.
- 어떻게 검증했나: npx serve로 열고 Network 탭에서 GET friend.json 200 확인. 파일 이름을 틀리게 바꿔 404 → 오류 문구가 뜨는지 확인. 빈 배열 파일로 빈 상태 확인.
```

PR 한 줄: `AI USE NOTE: Codex / fetch + 3상태 초안 / spinner 거절·response.ok 추가 / Network 탭 200·404 확인`

## 예시 2 · 개인 과제 (ChatGPT Edu, 코드 설명)

```
AI USE NOTE
- 어떤 도구: ChatGPT Edu
- 어떤 작업을 맡겼나: 5주차에 받은 TAG 중 "메뉴가 키보드로 안 열려요"의 원인 찾기. 내 script.js를 붙여 넣고 "왜 Enter로 안 열리는지 설명만 해 줘, 고치지는 말고"라고 요청.
- 무엇을 판단했나: 원인이 div를 버튼처럼 쓴 것이라는 설명을 받아들임. AI가 제안한 tabindex + keydown 처리는 쓰지 않고, div를 button 요소로 바꾸는 더 단순한 방법을 택함.
- 어떻게 검증했나: Tab으로 이동해 Enter·Space로 열리는지 확인. 기존 클릭도 되는지 확인. 콘솔 오류 없음.
```

## 하지 않을 것

- 학생 실명, 팀 내부 대화, 키·비밀을 AI에게 넣지 않습니다. 넣어야 하면 익명화합니다.
- "AI가 다 했다"도, "AI를 안 썼다"도 거짓이면 쓰지 않습니다. 쓴 만큼 적습니다.
- 개인 회고(15주차)는 AI LIMITED입니다. 맞춤법·구조 정리만 맡기고, 그렇게 했다고 밝힙니다.
