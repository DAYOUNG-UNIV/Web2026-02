01

소개 내용과 아이디어

나를 소개하는 내용과 이번 학기에 만들고 싶은 웹사이트 아이디어를 말합니다. 아이디어는 이후 바뀌어도 됩니다.

HTML 구성과 이유

제목·문단·목록·링크 중 한 부분을 짚고, 그 구성을 선택한 이유를 설명합니다.

03

AI 활용과 직접 수정

AI에 어떤 도움을 요청했는지, 결과에서 무엇을 채택하거나 고쳤는지 사례 하나를 보여 줍니다.

들으며 참고할 점 · 소개 내용이 본인을 잘 설명하는지, HTML 구성이 내용을 읽는 데 도움이 되는지, 선택·수정 이유를 설명할 수 있는지 살펴봅니다. 조원의 페이지에서 참고하고 싶은 점이나 궁금한 점을 하나 말합니다.
공유할 범위와 AI를 사용하지 않은 경우

본인이 공유할 내용만 보여 줍니다. REFLECTION이나 AI 대화 원문을 공개할 필요는 없습니다. AI를 사용하지 않았다면 직접 작성하거나 참고 자료를 활용한 과정을 소개합니다. AI가 기억하는 정보가 없어 관련 분석을 생략했다면 그 이유만 설명합니다.

04 / 지난 과제 · 도입

조별 우수작 선정 기준

모든 조원의 소개를 들은 뒤 아래 기준을 적용해 우수작 한 개를 선정합니다.

01

내용의 충실성

본인의 소개와 현재 웹사이트 아이디어가 드러나며, 사실과 다른 AI의 추론은 검토했는가?

02

HTML 구성

제목·문단·목록·링크가 내용의 역할에 맞게 쓰였으며, 읽는 순서와 필요한 링크를 확인했는가?

03

수정과 확인의 설명

직접 또는 AI의 도움으로 작성한 부분의 선택 이유와 확인 방법을 구체적으로 설명할 수 있는가?

위 기준을 종합해 선정 이유를 한 문장으로 정합니다. CSS 사용량, 화려한 효과, 유료 AI 사용 여부는 선정 기준이 아닙니다. 의견이 나뉘면 수업에서 함께 배우고 싶은 사례를 중심으로 결정합니다.

선정된 작성자가 발표를 맡고, 조원들은 질문별 답과 활용 사례를 정리해 전달합니다. 우수작 선정과 별개로 모든 조원의 사례를 토의 결과에 포함할 수 있습니다.

index.html에 “만들고 싶은 웹사이트” 항목을 추가해 주세요.

CSS·JavaScript·새 개인정보는 추가하지 않습니다.
AI가 파일을 바로 바꾸고 저장할 수도 있습니다. 요청 전 사본을 확보하고, 바뀐 파일과 줄을 확인합니다. 적용·되돌리기 버튼의 유무와 이름은 세션 방식에 따라 다릅니다.

먼저 설명

첨부한 index.html에서 label과 입력의 연결을 설명해 주세요.
파일은 수정하지 말고 연결이 빠진 항목만 알려 주세요.

그다음 수정

index.html의 날짜 입력에 label을 연결해 주세요.
다른 항목과 순서는 유지합니다.
CSS·JavaScript·외부 패키지는 추가하지 않습니다.
변경한 줄과 확인 방법을 설명해 주세요.
버전에 따라 Ask·Edit·Agent 등 선택 항목과 적용 방식이 다릅니다. 파일이 바로 수정·저장되는 경우도 있으므로 수락 버튼이 나오기만 기다리지 않습니다. 작업 전 사본이나 커밋을 확보하고 응답의 변경 파일 또는 Source Control에서 diff를 확인합니다.

이번 초안에는 패키지 설치·배포가 필요하지 않습니다. 작업 폴더와 범위를 확인하고 이유를 설명할 수 없는 명령은 실행 전에 질문합니다. 중지 버튼을 눌러도 이미 적용된 변경이 모두 취소되는 것은 아닙니다.

프로젝트 폴더를 열고 Live Server 확장(Ritwick Dey)의 설치 상태를 확인합니다. 준비되어 있다면 다시 설치하지 않습니다.

Live Server는 개발 중 미리보기를 돕습니다. 주문 저장·계정 인증용 서버를 자동으로 만들거나, 외부 서비스의 모든 CORS 제한을 없애 주는 것은 아닙니다.

29 / 준비와 HTML 구조보충·참고
strong·em·b는 글에서 서로 다른 역할을 합니다
중요한 내용, 말의 강세, 주의를 끌 단어를 HTML 요소로 구분합니다.
확인할 것 · 세 문장에서 표시된 부분이 어떤 역할인지 설명합니다. 마지막 문장의 b를 strong으로 바꾼 뒤, 모양이 같아도 의미가 같은지 생각해 봅니다.
strong은 중요성, em은 강세를 나타냅니다. b는 중요성을 더하지 않고 주의를 끌 부분에 사용합니다. 검색 순위나 음성 억양이 항상 달라진다고 보장하지 않습니다.


30 / 준비와 HTML 구조
figure·details도 내용의 역할을 나타냅니다
figure와 figcaption은 독립적인 내용과 설명을 묶고, details와 summary는 접고 펼칠 설명을 만듭니다.
확인할 것 · “이용 전 확인할 내용”을 눌러 펼칩니다. summary의 글과 figcaption을 바꾸어 각 역할을 확인합니다.
figure에는 이미지뿐 아니라 도해·표·코드 등 독립적으로 설명할 내용도 들어갈 수 있습니다. details는 HTML만으로 여닫을 수 있습니다. 태그 이름은 위치나 장식 모양만으로 선택하지 않습니다.
time · 사람과 프로그램이 읽을 날짜
<time datetime="2026-09-13">2026년 9월 13일</time>
화면에 읽기 편한 날짜를 쓰고 datetime에 기계가 읽을 형식을 지정할 수 있습니다. time을 사용한다고 알림이나 예약 기능이 만들어지는 것은 아닙니다.

시맨틱 HTML은 문서 요소를 의미에 맞게 사용하는 것입니다. 시맨틱 웹은 데이터와 관계를 기계가 처리하도록 표현하는 더 넓은 개념입니다. 태그만 바꾼다고 검색 순위나 모든 보조 기술의 읽기 방식이 일정하게 바뀌는 것은 아닙니다.

32 / 준비와 HTML 구조보충·참고
요소 안에 넣을 수 있는 내용을 확인합니다
div는 내용을 묶고 p는 문단을 나타냅니다. 문단 안에 또 다른 div를 넣는 구조는 올바르지 않습니다.
확인할 것 · 바깥 div 안의 p와 div를 찾습니다. 각 여는 태그와 닫는 태그가 어디에서 짝을 이루는지 확인합니다.
들여쓰기는 포함 관계를 읽는 데 도움이 됩니다. 어떤 요소를 안에 넣을 수 있는지는 각 HTML 요소의 규칙에 따릅니다. 잘못 중첩하면 브라우저가 구조를 보정할 수 있습니다.
포함 관계 읽기
div · 전체 묶음
├─ p · 첫 번째 문단
└─ div · 별도의 내용 묶음
이 예제에서는 두 내용이 바깥 div 안에 나란히 포함됩니다. p 안에 다른 div가 들어가는 구조가 아닙니다.
예를 들어 a는 문맥에 따라 문단과 같은 내용을 감쌀 수 있지만, 링크 안에 다른 링크를 중첩하지 않습니다.

  • 글로 나열했을 때와 페이지로 보았을 때 무엇이 달랐나요? 제목·목록·링크 중 도움이 된 구성을 찾습니다.

누가 사용할지, 어떤 기능을 넣고 싶은지 이야기합니다.

197 / 부록 · GitHub 저장소와 협업보충·참고
push·fetch·pull의 방향을 구분합니다
내 파일을 저장하는 것과 원격 이력을 주고받는 것은 별도의 동작입니다.
push ↑내 로컬 커밋을 원격으로 전달
→
fetch ↓원격 이력을 가져와 추적 정보 갱신
→
pull ↓ + 통합가져온 이력을 현재 브랜치에 통합
상황확인할 점
커밋했는데 GitHub에 안 보임push 여부와 대상 원격·브랜치 확인
fetch했는데 작업 파일이 그대로임fetch는 작업 파일에 자동 통합하지 않음
pull에 실패함로컬 변경·갈라진 이력·권한·네트워크 등 메시지 확인
git fetch
git pull --ff-only
git push
pull의 통합 방식은 옵션과 설정에 따라 fast-forward, merge, rebase 등으로 달라집니다. --ff-only는 단순히 앞으로 이동할 수 없으면 중단합니다. 거절 메시지를 force push로 바로 덮어쓰지 않습니다.

병합 충돌과 해결할 내용
충돌은 어느 변경을 남길지 자동으로 정할 수 없는 상태입니다.
<<<<<<< HEAD
h1 { color: #1b6e68; }
=======
h1 { color: #9d2a62; }
>>>>>>> menu-improvement
차이 확인양쪽 변경의 목적 확인
→
내용 결정한쪽 또는 합친 규칙으로 수정
→
표시 제거충돌 기호가 남지 않게 정리
→
검증·기록실행 결과 확인 후 stage와 commit
파일 전체에서 충돌 위치를 확인합니다. 자동으로 한쪽을 모두 선택하면 필요한 변경을 잃을 수 있습니다. 아직 커밋하지 않은 수정도 먼저 확인합니다.

.gitignore는 새 파일을 추적할지 판단할 때 사용하는 패턴입니다.
# 로컬 환경과 비공개 메모 예

private-notes/
Thumbs.db
.DS_Store
이미 커밋한 파일은 .gitignore에 이름을 추가한다고 이력에서 사라지지 않습니다. 비밀번호·토큰·개인정보가 포함되었다면 해당 정보와 이력의 노출을 별도로 처리해야 합니다.
이번 연습 저장소에는 개인정보 없는 예제만 넣습니다. 학생 자기소개와 REFLECTION을 일괄 추가하는 git add .부터 실행하도록 안내하지 않습니다.

GitHub 저장소·Pages의 역할과 사용 조건
저장소 주소

설정한 소스와 배포 과정으로 HTML·CSS·JavaScript가 서비스됩니다. 서버 주문 처리나 데이터베이스 기능이 자동으로 제공되지는 않습니다.
Pages의 사용 조건은 계정·요금제·저장소와 설정에 따라 다릅니다. 수업 자료가 공개되어 있다는 이유로 개인 과제도 공개해야 하는 것은 아닙니다.
