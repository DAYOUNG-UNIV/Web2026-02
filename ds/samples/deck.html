01

웹은 요청과 응답

URL · 메서드 · 상태 코드 · JSON

강의 1

URL은 "어디의 무엇을 어떻게" 한 줄

https://api.example.kr/v1/works?q=빛&page=2
  1. 호스트api.example.kr · 요청을 받을 서버
  2. 경로/v1/works · 서버 안의 자원
  3. 쿼리q=빛&page=2 · 요청의 조건

학생에게 수업 페이지 URL을 직접 나누어 읽게 합니다.

  • #조각은 서버로 가지 않는다는 점을 짚습니다.
강의 1

상태 코드는 첫 자리부터 읽습니다

2xx

성공 · 200 OK, 201 Created. 받은 데이터를 그립니다.

4xx

요청한 쪽 문제 · 400, 401, 404. 무엇을 고칠지 알려 줍니다.

5xx

서버 문제 · 500, 503. 다시 시도할 길을 둡니다.

개발자 도구 Network 탭을 열어 실제 요청 하나의 상태 코드를 같이 봅니다. 단축키: Windows F12, macOS ⌥⌘I.

실습 · 20분

연습용 서버에서 목록 받아 그리기

  • 먼저 실행만 해 보고, 네트워크 탭에서 GET /api/works 줄을 눌러 응답 본문을 같이 읽습니다.
  • 다음으로 서버 탭에서 작품을 하나 더 넣고 다시 실행합니다.
  • 확인 필요: 확장판의 실습 2(테스트 포함)는 숙제로 돌릴지 수업 중에 할지.
02

비동기와 fetch

기다리는 동안 멈추지 않기 · 세 가지 상태 · 저장

강의 2

fetch는 네 단계로 읽습니다

  1. 요청await fetch(url)
  2. 상태 확인if (!res.ok) throw …
  3. 본문 읽기await res.json()
  4. 그리기render(works)
async function loadWorks() {
  const res = await fetch('/api/works');
  if (!res.ok) throw new Error('서버 응답 ' + res.status);
  render(await res.json());
}

식당 진동벨 비유를 씁니다. 두 번 기다린다는 점(헤더, 본문)을 강조합니다.

강의 2 · 자주 하는 실수

fetch는 404에도 실패하지 않습니다

const res = await fetch(url);
const works = await res.json();
render(works); // 404여도 여기까지 옴
const res = await fetch(url);
if (!res.ok) {
  throw new Error('서버 응답 ' + res.status);
}
render(await res.json());

404 응답의 본문은 오류 설명 객체입니다. 검사하지 않으면 엉뚱한 곳에서 TypeError가 납니다.

실습 1의 주소를 /api/nothing으로 바꾸어 실제 오류 문장을 보여 줍니다.

강의 2

세 가지 상태, 그리고 저장

  1. 로딩"불러오는 중…"을 요청 전에 보여 줍니다.
  2. 빈 목록"아직 작품이 없습니다"와 다음 할 일.
  3. 오류상태 코드에 맞는 문장과 다시 시도 버튼.
// 저장
const text = JSON.stringify(memos);
localStorage.setItem('memos-v1', text);

// 복원
const saved = localStorage.getItem('memos-v1');
const memos = JSON.parse(saved) ?? [];

비밀번호, 학번, API 키는 저장하지 않습니다.

9주차 메모 앱에 저장을 더하는 실습은 확장판 실습 3으로 안내합니다.
