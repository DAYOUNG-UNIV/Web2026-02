데이터를 가져오는 웹

브라우저는 URL로 요청하고 서버는 상태 코드와 JSON으로 답합니다. fetch로 받아 로딩·빈 목록·오류 세 상태를 그리고, 이 브라우저에만 남길 것은 localStorage에 저장합니다.

  • 읽는 시간 약 10분
  • 자세한 설명과 실습 확장판

학습 목표

  1. 요청과 응답을 URL, 메서드, 상태 코드, 헤더로 나누어 읽는다.
  2. fetch와 async/await로 JSON을 받아 세 가지 상태와 함께 그린다.
  3. localStorage에 JSON으로 저장하고 복원한다.
  4. API 키와 CORS 때문에 서버를 거쳐야 하는 경우를 설명한다.

오늘의 지도

  1. 요청fetch(url)
  2. 상태 확인res.ok
  3. 본문 읽기res.json()
  4. 그리기render(data)

핵심 개념

요청과 응답

HTTP 요청은 메서드와 URL, 헤더, 본문으로 이루어지고, 응답은 상태 코드와 헤더, 본문으로 이루어집니다.

GET /api/works?q=빛     →     200 OK
                              Content-Type: application/json
                              [{ "id": 1, "title": "빛의 시간표" }]

URL의 #조각은 서버로 가지 않습니다. 서버에 조건을 보내려면 ?이름=값을 씁니다.

JSON

JSON은 객체와 배열을 글자로 적는 형식입니다. 키는 큰따옴표, 마지막 쉼표 없음, 주석 없음.

const text = JSON.stringify({ title: '소리 지도' }); // 객체 → 문자열
const obj = JSON.parse(text);                        // 문자열 → 객체

{ title: '소리 지도', }는 JavaScript에서는 맞지만 JSON으로는 틀립니다. res.json()이 SyntaxError를 냅니다.

fetch와 async/await

fetch는 결과 대신 Promise를 돌려줍니다. async 함수 안에서 await로 기다리면 위에서 아래로 읽히는 코드가 됩니다.

async function loadWorks() {
  const res = await fetch('/api/works');
  if (!res.ok) throw new Error('서버 응답 ' + res.status);
  return res.json();
}

fetch는 404·500에도 실패하지 않습니다. res.ok를 검사하지 않으면 오류 객체가 목록 자리에 들어갑니다.

세 가지 상태

데이터를 가져오는 화면에는 로딩, 빈 목록, 오류 세 상태마다 사용자가 읽을 문장이 있어야 합니다.

status.textContent = '불러오는 중…';
try {
  const works = await loadWorks();
  status.textContent = works.length ? '' : '아직 작품이 없습니다.';
  render(works);
} catch (err) {
  status.textContent = '불러오지 못했습니다 · ' + err.message;
}

localStorage

이 브라우저에만 남는 저장소입니다. 문자열만 넣을 수 있으므로 JSON으로 바꾸어 저장합니다.

localStorage.setItem('memos-v1', JSON.stringify(memos));
const memos = JSON.parse(localStorage.getItem('memos-v1')) ?? [];

비밀번호, 학번, 연락처, API 키는 넣지 않습니다. 개발자 도구로 누구나 읽을 수 있습니다.

API 키와 CORS

브라우저 코드는 공개됩니다. 키가 필요한 외부 API는 우리 서버를 거쳐 부르고, 키는 서버의 .env에 둡니다. 다른 출처의 응답은 상대 서버가 허락해야 읽을 수 있습니다(CORS).

키를 커밋했다면 파일에서 지우는 것으로 끝나지 않습니다. 발급처에서 바로 폐기하고 새로 받습니다.

확인 문제

Q1목록을 읽어 오는 요청에 알맞은 메서드는?

  • 읽기는 GET입니다. 서버의 데이터를 바꾸지 않습니다.

  • POST는 새 자원을 만들 때 씁니다.

  • DELETE는 자원을 지웁니다.

Q2서버가 404로 답하면 await fetch(url)는?

  • 거부는 응답을 아예 받지 못했을 때입니다.

  • 404도 응답입니다. 직접 검사해야 합니다.

Q3JSON으로 올바른 것을 모두 고르세요.

  • 키가 큰따옴표로 감싸져 있습니다.

  • 키에 큰따옴표가 없습니다.

  • 배열도 JSON입니다.

  • 마지막 쉼표는 JSON에서 허용되지 않습니다.

Q4객체를 localStorage에 넣기 전에 문자열로 바꾸는 함수는?

JSON.stringify입니다. 꺼낼 때는 JSON.parse를 씁니다.

Q5날씨 API 키를 어디에 두어야 하나요?

  • 브라우저 코드는 누구나 볼 수 있습니다.

  • 개발자 도구로 누구나 읽을 수 있습니다.

  • 서버가 키를 붙여 대신 부르고, 브라우저에는 결과만 줍니다.
