컴포넌트는 무엇을 대신하나

9주차에는 상태가 바뀔 때마다 render(state)를 직접 불렀습니다. React에서는 상태를 바꾸기만 하면 화면을 다시 그리는 일은 React가 합니다. 그 대가로 빌드 도구와 새 문법(JSX)이 늘어납니다.

let works = [];
function render() {
  list.innerHTML = works
    .map((w) => `<li>${w.title}</li>`)
    .join('');
}
works.push(newWork);
render(); // 잊으면 화면이 안 바뀜
function WorkList() {
  const [works, setWorks] = useState([]);
  // setWorks를 부르면 React가 다시 그림
  return (
    <ul>
      {works.map((w) => <li key={w.id}>{w.title}</li>)}
    </ul>
  );
}

PowerShell에서 npm 실행이 막히면 실행 정책 오류일 수 있습니다. 오류 문장을 그대로 복사해 eTL 메시지로 보내 주세요.

JSX의 세 가지 규칙

JSX는 JavaScript 안에 쓰는 HTML처럼 보이지만, 몇 가지가 다릅니다.

하나로 감싸기
컴포넌트는 요소 하나를 돌려줍니다. 여러 개라면 <>…</>로 감쌉니다.
className
class는 JavaScript 예약어라서 className을 씁니다.
{ }는 값
중괄호 안에는 문장이 아니라 값이 들어갑니다. if 대신 조건 ? A : B를 씁니다.

목록을 map으로 그릴 때 key를 빼면 콘솔에 경고가 납니다. 배열의 순서(index)가 아니라 데이터의 id를 key로 씁니다.

useEffect로 목록 불러오기

React 없이 컴포넌트처럼 쓰기

함수가 데이터를 받아 HTML 문자열이나 요소를 돌려주게 만들면, 프레임워크 없이도 컴포넌트처럼 나눌 수 있습니다. 작은 프로젝트라면 이것으로 충분합니다.

function WorkCard(work) {
  const li = document.createElement('li');
  li.textContent = work.title;
  return li;
}
list.replaceChildren(...works.map(WorkCard));
