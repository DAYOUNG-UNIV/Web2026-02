JavaScript 기초

값을 계산하고, 입력에 반응하고, 화면의 내용을 바꿉니다. HTML은 내용과 구조, CSS는 표현, JavaScript는 실행할 동작을 맡습니다. 디자인 기준(DESIGN.md·Bootstrap·Tailwind)에서 출발해 값·함수·DOM·이벤트·배열을 거쳐, 선택에 따라 결과가 달라지는 페이지까지 연결합니다.

  • 읽는 시간 약 10분
  • 자세한 설명과 실습 확장판 · 수업용 발표
  • 과제 과제 3(온라인 사진 전시회)을 수업 시작에 공유 · 조별 활동은 수업 중 진행

학습 목표

  1. 디자인 기준을 DESIGN.md에 적고, 직접 CSS·Bootstrap·Tailwind 세 방식의 차이를 설명할 수 있다.
  2. 숫자와 문자열을 구별하고, 입력 문자열을 숫자로 바꾼 뒤 계산·비교할 수 있다.
  3. 함수를 정의한 뒤 호출하고, 출력(console.log)과 반환(return)을 구별할 수 있다.
  4. 요소를 선택해 클릭·입력·제출 이벤트에 함수를 연결하고, 상태가 바뀌면 화면을 다시 그릴 수 있다.
  5. 배열과 반복으로 질문·선택지·결과 데이터를 다루고, 오류 메시지와 기대 결과로 코드를 확인할 수 있다.

  1. 입력사용자가 버튼을 누르거나 값을 입력합니다.
  2. 처리현재 값을 읽고 조건에 따라 계산합니다.

코드는 결과 예상 → 실행 → 한 곳 수정 → 다시 실행의 순서로 읽습니다. 화면이 바뀌었다면 어떤 값과 문장이 그 변화를 만들었는지 찾습니다.

핵심 개념

디자인 기준을 DESIGN.md에 적습니다

디자인 시스템은 여러 화면에서 함께 쓰는 디자인 기준과 재사용 요소를 모아 관리하는 체계입니다. 색과 간격을 정한 이유, 반복할 규칙을 DESIGN.md에 남기고, "주요 동작 색은 #0f766e" 같은 기준은 CSS 변수 --color-action으로 옮겨 버튼과 링크가 같은 값을 참조하게 합니다.

## 공통 값
- 주요 동작 색: #0f766e
- 본문: 1rem, 줄간격 1.7
## 사용 규칙
- 버튼 문구는 실행할 동작을 적는다.
- 키보드 초점은 테두리로 표시한다.

DESIGN.md를 저장하는 것만으로 브라우저 화면이 바뀌지는 않습니다. 파일을 읽은 사람이나 도구가 HTML·CSS에 반영해야 합니다.

Bootstrap과 Tailwind · 같은 버튼을 세 가지 방식으로

CSS 프레임워크는 반복해서 사용하는 스타일과 작성 규칙을 모아 둔 도구입니다. Bootstrap은 btn btn-primary처럼 준비된 컴포넌트 클래스를, Tailwind CSS는 px-4·bg-teal-700처럼 작은 유틸리티 클래스를 조합하며, Tailwind는 HTML에 쓴 클래스 이름을 도구가 찾아 CSS 파일을 생성해야 브라우저가 읽습니다.

<button type="button" class="exhibit-button">관심 작품에 추가</button>      <!-- 직접 CSS -->
<button type="button" class="btn btn-primary">관심 작품에 추가</button>     <!-- Bootstrap -->
<button type="button" class="bg-teal-700 px-4 text-white">관심 작품에 추가</button>  <!-- Tailwind -->

클래스 이름만 적고 CSS를 연결하지 않으면 서식이 적용되지 않습니다. Tailwind에는 Bootstrap의 btn-primary가 기본으로 없으므로, AI에 수정을 요청할 때 Bootstrap 5인지 Tailwind 4인지를 함께 알려줍니다. DESIGN.md와 프레임워크 사용은 선택 사항입니다.

JavaScript의 역할과 실행 환경

HTML은 어떤 입력과 버튼이 필요한지, CSS는 어떻게 배치할지, JavaScript는 클릭하거나 입력한 뒤 무엇이 달라질지를 맡습니다. const·함수는 언어 문법(표준 이름은 ECMAScript)이고 document.querySelector는 브라우저가 제공하는 DOM API이며, 수업 예제는 script.js를 defer로 연결하고 결과와 오류는 개발자 도구의 Console(F12)에서 봅니다.

<link rel="stylesheet" href="style.css">
<script src="script.js" defer></script>   <!-- 문서 해석이 끝난 뒤 실행 -->

페이지 내용이 보이더라도 script.js 경로가 틀리면 동작은 실행되지 않습니다. Console에서 console.log("시작") 아래에 보이는 undefined는 호출의 반환값이지 오류가 아닙니다.

값·변수·자료형

변수는 값에 붙인 이름입니다. 다시 대입하지 않을 값은 const, 바뀌는 값은 let으로 선언하고, =는 같다는 뜻이 아니라 오른쪽 값을 왼쪽 변수에 대입하는 기호입니다. 수량 2는 숫자, 화면에 표시할 "2"는 문자열, 선택 여부 true는 불리언이며 typeof로 종류를 확인합니다.

const price = 3000;      // 다시 대입하지 않을 값
let quantity = 1;        // 바뀌는 값
quantity = 2;            // 재대입
console.log(price * quantity);                  // 6000
console.log(typeof 2, typeof "2", typeof true); // number string boolean

total = price * quantity를 한 번 계산한 뒤 quantity만 바꾼다고 total이 자동으로 다시 계산되지는 않습니다. 계산문을 다시 실행해야 합니다.

연산·비교·변환 · 입력 문자열은 숫자로 바꾼 뒤 계산합니다

+는 숫자를 더할 때도, 문자열을 이어 붙일 때도 쓰이므로 "2" + "2"는 "22"입니다. ===는 타입을 변환하지 않고 비교하고(2 === "2"는 false) ==는 변환할 수 있으므로, 기본 예제는 Number()로 직접 변환한 뒤 ===로 비교합니다. 아래 코드는 오류 없이 실행되지만 결과가 틀립니다. 한 곳을 고쳐 테스트를 통과시켜 보세요.

=는 대입, ===는 비교, %는 백분율이 아니라 나머지입니다. Number("")는 0이므로 빈 입력인지 먼저 확인합니다.

조건에 따라 다른 코드를 실행합니다

블록은 중괄호 { }로 여러 문장을 묶은 부분입니다. if의 조건이 true이면 첫 블록을, false이면 else의 블록을 실행하며 둘 다 실행하지는 않습니다. &&는 두 조건이 모두 참인지, ||는 하나라도 참인지 조합합니다.

const score = 85;
if (score >= 90) {
  console.log("A");
} else if (score >= 80) {
  console.log("B");          // 앞 조건이 거짓이고 이 조건이 참일 때
} else {
  console.log("C");
}

큰 범위 조건을 먼저 두면 세부 조건에 도달하지 못할 수 있습니다. 앞에서 참인 조건을 만나면 뒤의 else if는 실행하지 않습니다. 들여쓰기는 읽기 쉽게 할 뿐, 범위를 정하는 문법은 중괄호입니다.

함수 · 정의한 뒤 호출하고, 출력과 반환을 구별합니다

함수는 이름을 붙여 다시 실행할 수 있게 묶은 동작입니다. 정의만 하면 실행되지 않고 greet()처럼 호출해야 실행되며, 호출할 때 보내는 값이 인수, 정의에서 받는 이름이 매개변수입니다. console.log는 확인용 출력이고 return은 호출한 코드가 사용할 값을 돌려줍니다. 아래 함수는 6을 출력하지만 돌려주지는 않습니다.

return이 없는 함수의 반환값은 undefined이고, return을 만나면 그 함수의 실행이 끝납니다. 화살표 함수 (width, height) => width * height도 같은 계산을 하지만 this 동작이 달라 모든 함수를 그대로 치환하지는 않습니다.

객체 · 한 대상의 여러 정보를 묶습니다

객체는 값을 속성 이름과 짝지어 묶은 것입니다. 점 뒤에는 속성 이름을 직접 쓰고 대괄호 안에는 이름을 담은 문자열이나 변수를 넣으며, 속성에 들어 있는 함수를 메서드라고 부릅니다(document.querySelector에서 document는 문서 객체, querySelector는 메서드).

const exhibition = { title: "쉬는 시간", photoCount: 3 };
console.log(exhibition.title);       // 점: 이름을 직접 씀
const key = "title";
console.log(exhibition[key]);        // 대괄호: 변수에 담긴 이름 "title"
exhibition.title = "여행의 기록";    // const여도 속성 변경은 가능
console.log(exhibition.missing);     // 없는 속성은 undefined

const가 막는 것은 이름에 다른 객체를 다시 대입하는 일이고, 속성 변경까지 막지는 않습니다. artwork.key는 이름이 key인 속성을 찾고, artwork[key]는 key의 값을 속성 이름으로 씁니다.

DOM · 요소를 선택한 뒤 내용을 바꿉니다

DOM은 브라우저가 HTML을 읽어 요소와 텍스트를 객체로 만들고 부모·자식 관계로 연결한 구조입니다. querySelector에는 CSS 선택자와 같은 표기를 쓰고, 일반 문장은 textContent로 넣으며, 입력창의 현재 값 input.value는 type="number"여도 문자열입니다(숫자로 읽으려면 valueAsNumber).

const title = document.querySelector("#title");   // 일치하는 요소가 없으면 null
title.textContent = "새로운 제목";                  // 글자로 넣기
document.querySelector("#plain").textContent = "<strong>중요</strong>"; // 태그가 글자로 보임
document.querySelector("#markup").innerHTML = "<strong>중요</strong>";  // strong 요소가 생김
console.log(document.querySelectorAll("li").length);  // NodeList의 개수

선택한 요소가 null이면 textContent를 설정할 때 TypeError가 납니다. id 오타와 스크립트 실행 시점부터 확인합니다. 확인하지 않은 사용자 입력이나 외부 내용을 innerHTML에 그대로 넣지 않습니다.

이벤트와 화면의 상태 · 함수를 전달하고, 값이 바뀌면 다시 그립니다

이벤트는 클릭·입력처럼 발생한 일을 알리는 신호이고, addEventListener("click", showMessage)는 나중에 실행할 함수를 전달합니다(showMessage()는 지금 호출). 값만 바꾸면 화면은 이전 글자를 표시하므로 상태를 바꾼 뒤 render()처럼 textContent에 새 값을 넣고, 여러 스타일이 함께 바뀌는 상태는 classList.toggle("dark")로 클래스를 바꿉니다. 아래 버튼은 눌러도 횟수가 늘지 않습니다.

폼 제출은 form의 submit에 연결하고 event.preventDefault()로 기본 전송을 막습니다. 텍스트 입력의 change는 포커스를 잃을 때, input은 입력할 때마다 발생합니다.

배열과 반복 · 여러 항목에 같은 작업을 실행합니다

배열은 순서가 있는 값의 묶음으로, 첫 항목의 인덱스는 0이고 항목이 3개이면 마지막 인덱스는 2입니다. for (시작; 조건; 갱신)은 조건 → 본문 → 갱신 → 조건을 반복하고 forEach는 항목마다 함수를 호출하며, 목록을 반복해 createElement → textContent → appendChild로 요소를 만듭니다. 아래 반복은 한 번 더 실행됩니다.

i <= menus.length이면 범위를 벗어난 위치까지 접근해 undefined가 나옵니다. forEach 콜백의 return은 이번 콜백만 끝내며 break처럼 전체 반복을 중단하지 않습니다.

입력에서 결과까지 · 폼 입력을 읽어 검사하고 계산합니다

화면의 입력 → 값 읽기 → 검사 → 계산 → 결과 표시를 submit 처리 함수에서 연결합니다. 수량은 빈 값 → 숫자 변환 → 유한한 정수 → 허용 범위(1~5)의 순서로 확인하고, HTML의 required·min·max 검사에서 막히면 submit 이벤트가 발생하지 않습니다.

form.addEventListener("submit", (event) => {
  event.preventDefault();                 // 기본 전송을 막습니다
  const count = quantity.valueAsNumber;   // .value는 문자열, valueAsNumber는 숫자
  if (!Number.isInteger(count) || count < 1 || count > 5) {
    total.textContent = "수량을 1~5 사이의 정수로 입력하세요.";
    return;                               // 계산은 생략합니다
  }
  total.textContent = "합계: " + calculateTotal(price, count) + "원";
});

빈 숫자 입력의 valueAsNumber는 NaN이고 Number("")는 0이므로, 빈 입력과 실제로 입력한 0을 구별하려면 변환 전 문자열을 먼저 검사합니다. 브라우저 검사는 우회할 수 있어 실제 서비스에는 서버 측 검증도 필요합니다.

조별 활동 · 선택에 따라 결과가 달라지는 페이지

하나의 질문은 객체, 질문 여러 개는 배열로 적고, 선택지의 type이 점수의 속성 이름과 연결됩니다. 선택하면 해당 분류의 점수가 1 늘고 다음 질문으로 이동하며, questionIndex < questions.length가 false가 되면 결과 화면으로 갑니다. 화면 전환은 hidden으로, 키보드 초점은 title.focus()로 옮깁니다.

const questions = [
  { text: "전시에 들어서면 먼저 무엇을 하나요?",
    options: [ { text: "전체 동선을 둘러본다", type: "walk" },
               { text: "한 작품 앞에 머문다", type: "look" } ] }
];
const scores = { walk: 0, look: 0 };
scores[type] = scores[type] + 1;     // 선택지의 type을 속성 이름으로
if (questionIndex < questions.length) showQuestion(); else showResult();

scores.type은 문자 그대로 type이라는 속성을 찾습니다. 다시 시작할 때 질문 번호만 되돌리면 이전 응답의 점수가 남으므로 응답 기록과 점수를 함께 초기화합니다. 한 예제의 데이터(choices·category)를 다른 예제(options·type)에 붙이면 자동으로 호환되지 않습니다.

const total = ;                  // SyntaxError: 표현식이 빠짐 → 따옴표·괄호·값 확인
console.log(quanity);            // ReferenceError: 이름을 찾지 못함 → 오타·선언·범위 확인
const title = document.querySelector("#missing");
title.textContent = "새 제목";   // TypeError: null에는 설정 불가 → 선택자·실행 시점 확인

오류 메시지가 없다는 사실만으로 의도한 계산이 된 것은 아닙니다. "2" + 1은 오류 없이 "21"이 됩니다. 입력과 기대 결과("2" → 6000, ""·"0"·"6"·"2.5" → 입력 오류)를 먼저 적고 실제 결과와 비교합니다.

AI와 함께 · 5주차 요약

이번 주 등급은 AI ALLOWED입니다. 조별 활동에 AI를 사용한다면 합의한 질문·선택지·결과 표와 바꿀 동작을 전달하고, 생성된 코드가 표의 연결을 그대로 따르는지 조원이 함께 확인합니다.

  • 요청은 구체적으로 — 기준 파일(DESIGN.md), 바꿀 범위(버튼 한 종류), 확인할 결과(문구·간격·초점·좁은 화면)를 함께 적습니다. 수정을 요청할 때는 입력, 기대한 결과, 실제 결과를 함께 전달합니다. 예: "빈 수량에서는 안내 문구가 나와야 하는데 0원이 표시됩니다."
  • 검토 절차 — 목적 정하기(바꾸려는 동작과 유지할 HTML 구조) → 작은 변경 요청 → 변경한 코드 읽기(새 변수·함수·이벤트가 무엇을 하는지) → 예상 결과와 비교(정상·경계·빈 값·다시 시작). 수정 후에는 실패했던 입력과 원래 정상이었던 입력을 다시 실행합니다.
  • 사람이 판단할 지점 — 모르는 문법이 한꺼번에 추가되면 현재 배운 변수·함수·조건·반복으로 풀어 써 달라고 요청할 수 있습니다. AI가 수정했다고 설명한 내용과 직접 실행해 확인한 결과를 나누어 기록합니다. 도구 이름이 결과물의 품질을 정하지는 않습니다.

자가 점검 퀴즈

Q1console.log("2" + "2");의 출력을 쓰세요.

"22"입니다. +는 문자열을 이어 붙입니다. 숫자로 계산하려면 Number("2") + Number("2")처럼 먼저 변환합니다.

Q2버튼을 누를 때마다 showMessage가 실행되게 하려면?

  • 맞습니다. 나중에 실행할 함수를 전달합니다.

  • showMessage()는 지금 호출한 결과(undefined)를 전달하므로 이후 클릭에 반응하지 않습니다.

Q3const items = ["숲", "바다", "도시"];에서 마지막 항목의 인덱스를 쓰세요.

2입니다. 첫 항목의 인덱스는 0이므로 항목이 3개이면 마지막 인덱스는 items.length - 1, 즉 2입니다.

Q4function showOnly(value) { console.log(value); }를 const r = showOnly(6000);으로 호출하면 r의 값은?

  • 6000은 Console에 출력된 값이지 돌려준 값이 아닙니다.

  • 맞습니다. return이 없는 함수의 반환값은 undefined입니다.

  • 오류 없이 실행됩니다. 출력과 반환을 구별합니다.

Q5사용자가 입력창에 적은 글을 화면의 문단에 보여 줄 때 기본으로 쓰는 속성은?

  • 맞습니다. 일반 문장은 글자로 넣습니다. 태그 문자가 있어도 그대로 보입니다.

  • innerHTML은 문자열을 HTML로 해석하므로, 확인하지 않은 사용자 입력이나 외부 내용을 그대로 넣지 않습니다.

  • value는 입력창의 현재 값을 읽을 때 씁니다.

Q6DESIGN.md와 CSS 프레임워크에 대한 설명으로 맞는 것을 모두 고르세요.

  • 맞습니다. 브라우저는 생성된 CSS를 읽으므로, 새 클래스를 쓰면 CSS를 다시 생성합니다.

  • Markdown 문서는 CSS로 실행되지 않습니다. 사람이나 도구가 HTML·CSS에 반영해야 합니다.

  • 맞습니다. 접히는 메뉴나 모달 같은 기능에만 별도의 JavaScript 파일이 필요합니다.

  • 제공되지 않습니다. AI에 요청할 때 어느 프레임워크의 몇 버전인지 함께 알려줍니다.
