CSS 레이아웃과 JavaScript 기초

지난주 폼과 자기소개 페이지를 공유한 뒤, 블록·인라인과 박스 크기에서 출발해 float·position·Flexbox·Grid·반응형으로 배치를 익혔습니다. 후반에는 JavaScript로 값을 계산하고 입력에 반응해 화면을 바꾸는 첫 단계를 다뤘습니다. 과제는 사진 3~5점으로 만드는 온라인 사진 전시회입니다.

  • 읽는 시간 약 10분
  • 자세한 설명과 실습 확장판
  • 과제 과제 3 · 온라인 사진 전시회 · 수업 활동

학습 목표

  1. 블록·인라인과 box-sizing으로 요소가 차지하는 자리와 너비를 계산하고, float·position이 문서 흐름을 어떻게 바꾸는지 설명할 수 있다.
  2. Flexbox로 한 방향의 정렬과 공간 배분을, Grid로 행과 열의 배치를 만들고, 두 방식을 언제 쓸지 고를 수 있다.
  3. 뷰포트 설정·상대 단위·미디어 쿼리로 화면 폭에 따라 배치를 바꾸고, 이미지가 부모 영역을 넘지 않게 할 수 있다.
  4. HTML·CSS·JavaScript의 역할을 구분하고, 변수·자료형·함수로 입력값을 계산하며 문자열 "2"와 숫자 2를 구별할 수 있다.
  5. querySelector로 요소를 찾고 addEventListener로 클릭·입력·제출에 반응해 textContent·classList로 화면을 바꿀 수 있다.

핵심 개념

기본 배치는 문서 순서를 따릅니다 · 블록과 인라인, 숨기기

별도의 배치 속성을 지정하지 않으면 요소는 HTML에 작성된 순서대로 놓입니다. p·div는 기본적으로 블록, span·a는 기본적으로 인라인 상자를 만듭니다. CSS로 숨긴 요소는 HTML 문서에 남아 있으며, 세 가지 방법은 자리와 키보드 초점이 서로 다릅니다.

display 값과 세 가지 숨기기
값줄과 자리크기 · 초점
block앞뒤 줄이 분리됨width·height 반영
inline문장 흐름에 놓임일반 텍스트 인라인의 width·height는 반영되지 않음
inline-block문장 흐름에 놓임width·height 반영
display: none자리가 없어짐초점 받지 않음
visibility: hidden자리 남음초점 받지 않음
opacity: 0자리 남음초점 받을 수 있음 · 클릭도 됨

display를 바꿔도 HTML의 의미와 중첩 규칙은 그대로입니다. p 안에 div를 넣는 구조는 올바르지 않고, 링크 안에 링크를 넣을 수 없습니다. opacity: 0은 투명하게 만들 뿐 클릭과 키보드 초점을 막지 않습니다. inline-block 사이에는 HTML 공백이 간격으로 나타날 수 있고 기본 정렬은 baseline입니다.

박스 모델과 너비 계산 · content-box와 border-box

내용(content), 안쪽 여백(padding), 테두리(border), 바깥 여백(margin)의 범위를 구분합니다. box-sizing에 따라 width에 포함되는 범위가 달라집니다. 기본값 content-box에서 width는 내용의 너비이고, border-box에서는 테두리까지의 너비입니다. 개발자 도구의 박스 모델 표시도 같은 네 영역으로 읽습니다.

.box { box-sizing: content-box; width: 200px; padding: 20px; border: 5px solid; }
/* 테두리까지 200 + 20×2 + 5×2 = 250px */
.box { box-sizing: border-box; }
/* 테두리까지 200px, 내용은 150px · margin은 두 방식 모두 지정 너비 바깥 */

width: 100%에 padding을 더하면 content-box에서는 부모를 넘칩니다. 같은 원리입니다. margin은 border-box의 지정 너비에도 포함되지 않습니다. 단위 없는 width: 200;은 표준 모드에서 무효이므로 새 문서는 <!DOCTYPE html>로 시작하고 px 같은 단위를 붙입니다.

float는 주변 글이 옆으로 흐르게 합니다 · clear와 부모 높이

웹 레이아웃은 표·프레임 → CSS(1996·1998) → float → 반응형(2010) → Flexbox·Grid 순서로 필요한 도구가 더해졌습니다. float는 이미지 옆으로 글이 흐르도록 배치할 때 씁니다. 여러 열의 페이지를 만드는 데에도 쓰였지만, 지금은 Flexbox와 Grid로 그런 배치를 구성합니다. 떠 있는 요소는 부모의 일반 흐름 높이 계산에서 빠집니다.

.picture { float: left; width: 120px; margin: 0 18px 12px 0; }
footer   { clear: both; }          /* 다음 영역만 float 옆에 오지 않게 */
.story   { display: flow-root; }   /* 부모가 안의 float를 포함하도록 */

clear와 부모의 높이는 다른 문제입니다. 자식이 모두 float이면 부모의 자동 높이에 자식 높이가 들어가지 않아 배경이 짧아지거나 뒤 내용과 겹칩니다. overflow: hidden으로 해결하면 내용까지 잘릴 수 있으므로 목적을 구분합니다. float로 만든 여러 열은 앞의 높은 카드가 다음 카드의 이동을 막아 기대한 행과 다르게 놓일 수 있습니다.

position으로 요소의 위치를 지정합니다 · 기준 상자

position의 기본값은 static입니다. relative는 자리를 유지하며 원래 위치에서 이동하고, absolute는 자리에서 빠져 기준 상자 안에 놓이며, fixed는 자리에서 빠져 보통 뷰포트에 고정되고, sticky는 자리를 유지하다 스크롤 경계에서 붙습니다. absolute의 기준 상자는 보통 가장 가까운 위치 지정 조상(position이 static이 아닌 조상)의 패딩 영역입니다. 아래 배지는 바깥 영역을 기준으로 놓여 있습니다. 카드가 기준이 되도록 고쳐 보세요.

relative로 이동해도 다음 항목은 밀려나지 않습니다. absolute로 바꾸면 다음 항목이 비워진 자리로 올라옵니다. sticky는 top 같은 경계값이 없으면 붙지 않고, 부모 영역이 끝나면 함께 사라지며, 조상에 overflow: hidden이 있으면 그 조상이 스크롤 기준이 될 수 있습니다. fixed 바가 본문을 가리면 바의 높이만큼 여백을 둡니다. 겹침은 같은 쌓임 맥락 안에서만 z-index로 비교합니다. 위치를 시각적으로 바꿔도 HTML의 읽기 순서는 바뀌지 않습니다.

부모에 display: flex를 적용합니다 · 주축과 교차축

Flexbox는 한 방향으로 아이템을 나열하고 공간을 배분하는 배치 방식입니다. 부모는 flex container, 직접 자식은 flex item이 됩니다. 주축(main axis)은 아이템을 놓는 방향이고 교차축(cross axis)은 그에 수직인 방향입니다. flex-direction: row면 주축이 가로, column이면 세로입니다. justify-content는 주축의 남는 공간을 배분하고, align-items는 교차축에서 모든 아이템을, align-self는 한 아이템만 정렬합니다. 아래 세 article이 한 줄에 12px 간격으로 놓이게 부모 한 곳만 고쳐 보세요.

display: flex는 부모에 지정합니다. 직접 자식만 아이템이 되고, 아이템 안의 요소까지 아이템이 되지는 않습니다. 주축은 항상 가로가 아닙니다. column이면 justify-content가 세로 방향의 남는 공간을 다룹니다. 남는 공간이 없으면 justify-content 값에 따른 차이가 작습니다. 아이템 사이 간격은 gap으로 따로 지정합니다. stretch는 교차축 크기가 auto인 아이템만 늘립니다.

줄바꿈·크기·순서 · flex-wrap, flex, order

한 줄에 들어가지 않을 때 flex-wrap: wrap은 다음 줄로 넘기고, nowrap은 한 줄을 유지하며 아이템을 줄입니다. flex는 flex-grow(남는 공간을 가져가는 비율), flex-shrink(부족할 때 줄어드는 비율), flex-basis(기준 크기)를 순서대로 적는 단축 속성입니다. order는 화면 배치 순서를, margin-left: auto는 그 줄의 남은 공간을 앞쪽 여백으로 가져갑니다.

.container { display: flex; flex-wrap: wrap; gap: 12px; }
.item      { flex: 1 1 160px; min-width: 0; }  /* 늘어남 / 줄어듦 / 기준 크기 */
.item:nth-child(2) { flex-grow: 2; }            /* 남는 공간을 두 배로 가져감 */
.item:nth-child(2) { order: -1; }               /* 화면 순서만 앞으로 */
.confirm   { margin-left: auto; }               /* 줄의 남은 공간을 앞 여백으로 */

flex-grow: 2는 남는 공간을 나누는 비율이지 최종 너비의 비율이 아닙니다. 줄어듦도 기준 크기와 최소 크기의 영향을 받습니다. order와 reverse는 화면 배치만 바꾸고 HTML 문서 순서는 그대로이므로, 바꾼 뒤 Tab으로 초점 순서가 화면과 충돌하지 않는지 확인합니다. Flexbox는 줄마다 공간을 따로 배분하므로 여러 행의 열 위치를 맞추려면 Grid를 씁니다.

격자를 만들고 영역을 지정합니다 · CSS Grid

부모에 display: grid를 지정하면 Grid 컨테이너가 되고 직접 자식이 아이템이 됩니다. grid-template-columns로 열 트랙을 만들고, fr은 고정 트랙과 gap을 뺀 남는 공간을 비율로 나눕니다. gap은 행 간격 열 간격 순서입니다. 배치는 ① 자동 배치 ② 시작선·끝선(grid-column: 2 / 4) ③ grid-area: 행 시작 / 열 시작 / 행 끝 / 열 끝 ④ grid-template-areas의 이름, 네 가지로 표현합니다.

body { display: grid; grid-template-columns: 2fr 1fr; gap: 12px;
       grid-template-areas: "head head" "main side" "foot foot"; }
header { grid-area: head; }  main   { grid-area: main; }
aside  { grid-area: side; }  footer { grid-area: foot; }
/* 선 번호로 같은 두 열: .item { grid-column: 2 / 4; }  → 2번 선부터 4번 선까지 */

열 수보다 세로 경계선이 하나 더 많습니다. 끝선 번호는 마지막 셀의 번호가 아닙니다. grid-template-areas에서 같은 이름은 직사각형이어야 하고, 떨어진 모양으로 적으면 그 선언이 무효가 됩니다. 이름을 붙이지 않는 칸은 점(.)으로 둡니다. 가로쓰기에서는 justify가 가로, align이 세로 방향입니다.

Flexbox와 Grid는 언제 사용할까요? · minmax와 조합

Flexbox는 한 행 또는 한 열의 공간 배분과 정렬(버튼 묶음·내비게이션·카드 내부)에, Grid는 행과 열을 함께 정의하는 배치(페이지 영역·카드 목록·정렬된 폼)에 씁니다. position은 흐름 위에서 오프셋이나 겹침이 필요한 부분(배지·고정 안내)에만 씁니다. repeat(auto-fit, minmax(180px, 1fr))는 화면 폭에 따라 열 개수를 바꿉니다.

.cards   { display: grid; gap: 12px;
           grid-template-columns: repeat(auto-fit, minmax(min(100%, 180px), 1fr)); }
.layout  { display: grid; grid-template-columns: 2fr 1fr; gap: 18px; }   /* 페이지 영역 */
.actions { display: flex; justify-content: flex-end; gap: 10px; }       /* 버튼 묶음 */
@media (max-width: 480px) { .layout { grid-template-columns: 1fr; } }

auto-fit은 비어 있는 반복 트랙을 접고 auto-fill은 빈 트랙 자리를 유지합니다. 긴 내용 때문에 열이 줄어들지 않으면 min-width: 0과 overflow-wrap도 살펴봅니다. 전체 페이지를 좌표(position)만으로 배치하지 않습니다. 카드 목록을 Grid로 배치하고 카드 안의 배지는 absolute로 놓는 식으로 함께 씁니다.

반응형 웹은 화면 크기를 하나로 가정하지 않습니다

고정 폭(줄지 않음)·유동 폭(공간에 맞춰 축소)·반응형(좁으면 배치 변경)은 다릅니다. 뷰포트 meta는 모바일 브라우저가 CSS 레이아웃 폭을 기기 폭으로 잡게 합니다. 상대 단위의 기준은 서로 다릅니다. width의 %는 부모 내용 영역, vw·vh는 뷰포트의 1%, em은 그 요소의 글꼴 크기, rem은 html의 글꼴 크기입니다. 미디어 쿼리는 조건에 맞을 때 CSS를 추가합니다. 기본 규칙을 먼저 쓰고, 내용을 읽고 조작하기 어려워지는 폭을 찾아 중단점으로 정합니다.

/* HTML head: <meta name="viewport" content="width=device-width, initial-scale=1"> */
.fields { display: grid; gap: 16px; }          /* 기본: 한 열 */
@media (min-width: 560px) {
  .fields { grid-template-columns: 1fr 1fr; }  /* 560px부터 두 열 */
}

maximum-scale=1이나 user-scalable=no로 사용자의 확대를 막지 않습니다. min-width 규칙은 기본 규칙을 없애는 것이 아니라 CSS 우선순위에 따라 함께 적용됩니다. 같은 50%와 50vw도 기준이 달라 결과가 다릅니다. 배치를 바꾼 뒤에는 좁게 → 넓게, 긴 메뉴 이름, 글자 확대, Tab 이동에서 가로 스크롤·겹침·잘림이 없는지 확인합니다.

확장판에서 더 보기

이미지가 부모 영역을 넘지 않게 합니다 · object-fit · picture · Gradient

width: 100%의 기준은 보통 부모의 내용 영역이고, height: auto는 원본 비율을 지킵니다. object-fit은 img 자신의 상자 안에 이미지를 넣는 방식입니다. contain은 전체 표시, cover는 비율을 지키며 잘라 채우기, fill은 비율이 달라질 수 있습니다. 같은 구도의 해상도 후보는 srcset·sizes로, 조건에 따라 다른 구도를 고를 때는 picture와 source로 제공합니다. Gradient는 색이 이어지는 CSS 이미지로 background-image에 지정합니다.

img        { width: 100%; height: auto; }               /* 부모를 넘지 않고 비율 유지 */
.frame img { height: 200px; object-fit: cover; }         /* 틀에 맞추고 일부를 잘라 채움 */
.banner    { background-color: #d8edf0;
             background-image: linear-gradient(90deg, #d8edf0, #e6d7f2); }

cover는 일부를 잘라냅니다. 잘리는 부분이 사진의 의미에 맞는지 전시 과제에서 판단합니다. picture의 source 조건이 맞지 않으면 img의 이미지를 씁니다. Gradient 배경에서는 가장 밝은 곳과 어두운 곳 모두에서 글자 대비를 확인하고, 중요한 상태를 색만으로 전달하지 않습니다. 사진을 외부 주소나 컴퓨터의 절대 경로로만 연결하면 다른 환경에서 열리지 않습니다.

JavaScript는 실행할 동작을 담당합니다 · 파일 연결과 Console

HTML은 내용과 구조, CSS는 표현과 배치, JavaScript는 클릭하거나 입력한 뒤 무엇을 계산·변경할지 담당합니다. JavaScript는 1995년 브라우저에서 시작했고 Java와는 별개의 언어입니다. ECMAScript는 언어 규칙의 표준 이름이고, 브라우저는 JS 엔진과 Web API(DOM·이벤트)를 제공합니다. document.querySelector는 언어 문법이 아니라 DOM API입니다. 이 수업은 index.html·style.css·script.js를 같은 폴더에 두고 외부 파일을 defer로 불러옵니다. defer 스크립트는 HTML 해석이 끝난 뒤 문서 순서대로 실행됩니다. Console은 실행 결과와 오류를 확인하는 창입니다.

<link rel="stylesheet" href="style.css">
<script src="script.js" defer></script>
<!-- Console: Windows F12 또는 Ctrl+Shift+I · macOS Option+Command+I -->
<!-- console.log("시작") 뒤의 undefined는 반환값이지 오류가 아닙니다 -->

페이지 내용이 보여도 script.js 경로가 틀리면 동작은 실행되지 않습니다. 파일 이름·대소문자·확장자를 확인합니다. defer 없이 head에서 불러오면 뒤의 요소를 너무 일찍 선택해 null이 나옵니다. details의 펼침·접힘과 기본 폼 유효성 검사는 HTML이 제공하는 동작이므로 JavaScript가 필요하지 않습니다.

변수는 값에 이름을 붙입니다 · 자료형 · 변환 · 조건 · 함수

선언은 이름을 만들고 대입은 값을 정합니다. =는 비교가 아니라 대입이고, 비교는 타입을 바꾸지 않는 ===를 씁니다. 우선 const로 선언하고 다시 대입할 때만 let을 씁니다. 숫자 2와 문자열 "2"는 typeof가 다르고, +는 숫자 덧셈과 문자열 연결에 모두 쓰이므로 입력값은 Number()로 바꾼 뒤 계산합니다. if (조건) { } else { }로 경우를 나눕니다. 함수는 다시 사용할 동작을 정의하고 호출해야 실행되며, return으로 결과를 돌려줍니다. 아래 addOne은 "2"에 1을 더해 "21"을 돌려줍니다. 숫자로 바꿔 보세요.

const는 재대입을 막을 뿐 객체 내부의 속성까지 고정하지 않습니다. Number("")는 0이므로 빈 입력인지 먼저 확인하고, 빈 숫자 입력의 valueAsNumber는 NaN입니다. 0.1 + 0.2는 0.3이 아니므로 금액은 원 단위 정수로 계산합니다. console.log는 확인용 출력이고, return이 없는 함수의 반환값은 undefined입니다. 백틱(`)은 작은따옴표와 다른 문자입니다.

DOM은 문서를 요소의 관계로 표현합니다 · 선택과 변경

DOM(Document Object Model)은 브라우저가 HTML을 읽어 요소와 텍스트를 객체로 만들고 부모·자식 관계로 연결한 구조입니다. document.getElementById("total")은 id 하나(#을 붙이지 않음), querySelector("#total")는 CSS 선택자에 처음 일치하는 요소 하나, querySelectorAll(".item")은 일치하는 요소들의 NodeList를 돌려줍니다. 점은 객체의 속성(정보)이나 메서드(함수)에 접근하고, 괄호는 호출입니다. 문장은 textContent로 넣고, 상태는 classList로 바꾸어 표현은 CSS에 맡깁니다.

const message = document.querySelector("#message");   // 없으면 null
message.textContent = "신청 내용을 먼저 확인하세요.";   // 일반 문장은 textContent
document.body.classList.toggle("dark");                // 상태는 클래스로, 표현은 CSS로
const item = document.createElement("li");
item.textContent = "추가 요청 사항 확인";
document.querySelector("#list").appendChild(item);     // 부모에 붙여야 화면에 보임

일치하는 요소가 없으면 querySelector는 null을 돌려주고, 그 뒤 .textContent를 쓰면 TypeError가 납니다. id 오타와 실행 시점부터 확인합니다. innerHTML은 문자열을 HTML로 해석하므로 확인하지 않은 사용자 입력이나 외부 내용을 그대로 넣지 않습니다. NodeList는 하나의 요소처럼 바로 바꾸지 않고 forEach로 순회합니다. 개발자 도구 Elements의 DOM은 JavaScript가 바꾼 뒤의 상태이며 파일 원문과 다를 수 있습니다.

이벤트가 발생하면 함수를 실행합니다 · 폼 입력 읽기와 오류 확인

이벤트는 클릭·입력처럼 발생한 일을 알리는 신호이고, 처리 함수는 그때 실행할 코드입니다. addEventListener의 첫 인수는 이벤트 이름, 두 번째 인수는 실행할 함수입니다. 버튼 활성화는 click, 입력할 때마다는 input, 선택 변경 후는 change, 폼의 최종 확인은 submit입니다. submit은 버튼 클릭과 Enter 제출을 함께 처리하고 event.preventDefault()로 기본 전송을 막습니다. 수량은 quantity.valueAsNumber로 숫자로 읽어 Number.isInteger와 범위로 검사한 뒤 output의 textContent로 결과를 표시합니다. 아래 코드는 버튼을 누르기 전에 문장이 바뀌고, 누르면 아무 일도 없습니다. 고쳐 보세요.

showMessage는 나중에 실행할 함수를 전달하고, showMessage()는 지금 호출합니다. 브라우저 유효성 검사(required·min·max)에서 막히면 submit 이벤트가 발생하지 않을 수 있습니다. 코드가 동작하지 않으면 파일 실행 → 요소 선택 → 값 읽기 → 이벤트 처리 순서로 console.log를 넣어 확인합니다. 오류는 이름부터 읽습니다. SyntaxError는 따옴표·괄호·값 누락, ReferenceError는 오타·선언 전 사용(quanity ≠ quantity), TypeError는 null에 속성 설정입니다.

Q1가운데 버튼을 보이지 않게 하되 자리는 남기고, 키보드 초점도 받지 않게 하려면?

  • 자리까지 없어집니다. 뒤의 요소가 올라옵니다.

Q2width: 200px; padding: 20px; border: 5px solid; box-sizing: content-box;일 때 테두리까지의 가로 너비는 몇 px인가요? (숫자만)

200 + 20×2 + 5×2 = 250px입니다. border-box로 바꾸면 테두리까지 200px, 내용은 150px이 됩니다. margin은 두 방식 모두 지정 너비 바깥입니다.

Q3카드 안의 배지(position: absolute; top: 12px; right: 12px)를 카드의 오른쪽 위에 놓으려면 카드에 무엇을 추가하나요?

  • 맞습니다. 이동 값 없이 지정하면 카드는 제자리에 있으면서 배지의 기준 상자가 됩니다.

  • 카드가 흐름에서 빠져 다음 항목이 비워진 자리로 올라옵니다. 기준만 잡을 때는 relative를 씁니다.

  • z-index는 겹침 순서일 뿐 기준 상자를 만들지 않습니다.

Q4flex-direction: row인 컨테이너에서 높이가 다른 아이템들을 세로 방향 가운데에 맞추려면?

  • 주축(가로)의 남는 공간을 배분합니다. 세로 정렬이 아닙니다.

  • 맞습니다. 교차축(여기서는 세로)에서 모든 아이템을 가운데에 맞춥니다. 한 아이템만 다르게 하려면 align-self를 씁니다.

  • 글자의 가로 정렬입니다. 아이템 상자의 위치는 바꾸지 않습니다.

Q5console.log("2" + "2");의 출력은 무엇인가요?

문자열 "22"입니다. +는 문자열을 이어 붙입니다. 숫자 4를 얻으려면 Number("2") + Number("2")처럼 바꾼 뒤 더합니다. "2" === 2는 false입니다.

Q6button.addEventListener("click", showMessage());에서 무엇이 문제인가요?

  • addEventListener의 이벤트 이름은 "click"이 맞습니다.

  • 맞습니다. 두 번째 인수는 나중에 실행할 함수입니다. 괄호를 붙이면 등록 시점에 한 번 실행되고 클릭에는 아무 일도 일어나지 않습니다.

  • 버튼을 포함한 모든 요소에 쓸 수 있습니다.

확장판에서 더 보기

눌러서 움직여 보는 모형들입니다. 요약에서 헷갈린 개념은 여기서 한 번 더 확인합니다.

  • 박스의 네 영역을 그림에서 구분합니다 — content → padding → border → margin을 눌러 보고 여백을 늘리면 전체 너비가 어떻게 달라지는지 숫자로 확인
  • 스크롤할 때 fixed와 sticky는 어떻게 다를까요? — 세 화면의 스크롤 위치를 함께 바꾸며 static·sticky·fixed 비교
  • Flexbox의 주축과 교차축 — 방향·주축 정렬·교차축 정렬을 바꾸며 A·B·C의 위치 비교, justify-content의 여섯 가지 배치
  • Grid의 선·트랙·셀·영역 — 용어 버튼으로 강조하고 네 가지 배치 표현을 같은 화면에서 비교
  • 한 줄씩 실행하면 값이 어떻게 바뀔까요? — 실행 줄·변수의 값·Console 출력이 단계마다 바뀌는 모형, 함수 호출 · 인수에서 반환값까지
  • HTML·DOM·화면에서 같은 대상을 찾습니다 — 저장된 HTML, 브라우저의 DOM, 렌더된 화면을 나란히 보고 이벤트 처리 함수의 등록과 실행

질문 창구

질문과 연락은 eTL 메시지로 보내 주세요(메일 확인이 어렵습니다). 수업 내용은 eTL 게시판에도 남길 수 있습니다. 질문에는 ① 하려던 작업 ② 수행한 절차 ③ 기대한 결과와 실제 결과(오류 화면)를 함께 적어 주시면 원인을 빨리 찾을 수 있습니다.

속성과 메서드를 다 외우지 않아도 됩니다. 제출한 전시 페이지의 style.css에서 규칙 하나를 바꾸어 보고, 왜 그렇게 보이는지 한 번만 말로 설명해 보세요. 그걸로 충분합니다.
