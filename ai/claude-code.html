Claude Code 따라 하기

Claude Code는 터미널에서 돌아가는 코딩 에이전트입니다. 저장소를 읽고, 파일을 고치고, 명령을 실행하되, 그때마다 사람에게 묻습니다. 세 가지 연습 화면에서 하네스 문서 만들기, fetch 기능 추가, 테스트와 리뷰를 따라 해 보고, 권한 요청을 읽고 답하는 순서를 몸에 익힙니다. 유료 플랜이 필요한 선택 도구이며, 쓰지 않아도 모든 과제는 ChatGPT Edu로 할 수 있습니다. 연습 화면은 로그인 없이 동작하며 실제 서비스가 아닙니다.

이 매뉴얼이 맞는 경우

잘 맞는 경우
  • 팀 저장소의 파일 여러 개를 읽고 고치고 테스트까지 돌리게 하고 싶을 때. 10주차 하네스 문서, 11주차 알파 버전, 12주차 테스트·리뷰가 그런 일입니다.
  • 이미 유료 플랜(Pro·Max·Team)이나 API 크레딧이 있을 때. 같은 원리의 무료 경로는 Codex(ChatGPT Edu 계정, 학교 설정 확인 필요)입니다.
과한 경우
  • 파일 한두 개의 설명이나 수정 제안만 필요할 때. ChatGPT Edu 웹에 붙여 넣는 편이 빠르고 범위도 분명합니다.
  • 비밀 키나 개인정보가 든 폴더를 다뤄야 할 때. 에이전트는 폴더 안의 파일을 읽을 수 있으므로 .env는 읽지 못하게 막고(04), 그런 자료는 어떤 AI 도구에도 넣지 않습니다.
먼저 할 것
6주차 Git·GitHub 실습(온라인 영상)과 터미널 기본(cd, ls, 10주차)을 한 번 해 봅니다. 이 페이지의 연습 화면은 설치 없이 됩니다. 실제 설치는 03을 따라 하되, 계정이 없으면 건너뛰어도 됩니다.

진행 상황을 표시하며 따라가세요. 표시는 이 브라우저에만 저장됩니다.

Claude Code란: 읽고, 바꾸고, 실행하고, 묻는다

채팅과 무엇이 다른지, 어떤 계정이 필요한지, 수업에서 어디까지 쓰는지를 먼저 정리합니다.

한 줄 정의

공식 문서의 첫 문장입니다. "Claude Code is an agentic coding tool that reads your codebase, edits files, runs commands, and integrates with your development tools." 터미널, VS Code 확장, 데스크톱 앱, 웹에서 쓸 수 있고, 이 페이지는 터미널만 다룹니다.

ChatGPT Edu 웹에서는 내가 파일을 붙여 넣고, 제안을 받아 내가 고치고, 내가 실행합니다. 에이전트는 그 가운데 둘을 대신합니다. 프로젝트 폴더 안의 파일을 스스로 읽고, 고치고, 명령을 실행합니다. 대신 고치거나 실행하기 전에 묻습니다. 그 질문에 답하는 순간이 이 수업에서 말하는 '사람이 확인하는 지점'입니다.

  1. 읽는다프로젝트 폴더의 파일, CLAUDE.md, 내가 @로 붙인 파일을 읽습니다. 읽기는 묻지 않습니다.
  2. 바꾼다파일을 만들거나 고칩니다. Manual 모드에서는 변경마다 diff를 보여 주고 허락을 구합니다.
  3. 실행한다테스트, 서버, git 같은 명령을 돌립니다. 읽기 전용 명령 외에는 허락을 구합니다.
  4. 사람이 확인한다diff를 읽고, 테스트 출력을 보고, 브라우저에서 눌러 봅니다. 이 단계는 어떤 도구에서도 빠지지 않습니다.

도구가 달라도 원리는 같습니다. Codex는 지시 파일 이름이 AGENTS.md이고 승인 방식이 샌드박스와 승인 정책 두 층으로 나뉘지만, 네 단계는 같습니다. 그래서 이 페이지를 Codex로 따라 해도 됩니다. 대응표는 Codex 안내에 있습니다.

계정과 비용

공식 문서 원문입니다. "Claude Code requires a Pro, Max, Team, Enterprise, or Console account. The free claude.ai plan does not include Claude Code access." 모든 학생이 무료로 쓸 수 있는 경로가 없으므로, 수업은 ChatGPT Edu를 기본으로 하고 Claude Code는 같은 원리를 연습하는 선택 도구로 둡니다. 유료 도구를 쓰는지 여부는 평가와 관계가 없습니다.

에이전트 루프와 '하네스'라는 말

내부 동작
요청을 받으면 gather context → take action → verify results를 반복합니다(문서의 agentic loop). 모델은 글을 만들 뿐이고, 파일 읽기·편집·셸 실행 같은 도구 호출은 모델을 둘러싼 프로그램 층이 실행합니다. 원문: "Claude Code is the layer around the model that provides the tools and manages the context the model sees. This surrounding layer is what the term agentic harness refers to." OT에서 배운 하네스 엔지니어링(문서·규칙·검사·기록)은 이 층에 우리가 넣는 것입니다. 작업 중 Esc를 누르면 멈추고, 작업 중에 친 메시지는 대기열에 들어가 도구 호출이 끝나는 대로 읽힙니다.
명세·문서
How Claude Code works · Overview · OT · Harness Engineering
트레이드오프
에이전트는 여러 파일을 스스로 읽고 고쳐 빠르지만, 읽은 파일이 모두 컨텍스트에 들어가 비용이 늘고 요청 밖으로 번지기 쉽습니다. 채팅은 내가 붙여 넣은 것만 보니 느리지만 범위가 분명합니다. 파일 두세 개 안의 일이면 채팅이, 저장소 전체의 규칙을 지키며 여러 파일을 고치는 일이면 에이전트가 맞습니다.
5분 실험
06의 fetch 실습에서 res.ok 검사를 넣기 전에 실행해 보세요. 에이전트가 "성공했다"고 말해도 404 요청에서 화면이 깨집니다. verify 단계는 도구가 아니라 내가 합니다.

금지선 네 가지와 이 도구에서 지키는 법

검증 없는 제출

비밀정보 입력
API 키·비밀번호는 요청에도 저장소에도 넣지 않습니다. 설정 파일에 "deny": ["Read(./.env)", "Read(./.env.*)"]를 두어 에이전트가 .env를 읽지 못하게 막습니다(04).
확인 안 한 정보·출처
에이전트가 말한 파일 이름, 함수 이름, 동작은 저장소를 열어 확인합니다. 에이전트가 읽은 웹 페이지의 내용도 마찬가지입니다.
무조건적 에이전트 권한
"Yes, and don't ask again"을 모든 명령에 주지 않고, --dangerously-skip-permissions로 시작하지 않습니다. 이 플래그는 사람이 확인하는 지점을 전부 없앱니다. 수업 노트북에서는 쓰지 않습니다(08).

AI가 다 해 줘도 되나요?

됩니다. 단 세 가지를 할 수 있어야 합니다. 설명(이 코드가 무엇을 하는지 내 말로), 검증(직접 실행하고 눌러 보고 테스트로), 판단(받아들일 것과 뺄 것을 내가 정함). 에이전트는 셋 중 어느 것도 대신해 주지 않습니다. 설명이 안 되는 조각이 있으면 "이 함수를 지금 배운 문법으로 풀어 써 줘"라고 다시 요청합니다.

AI USE NOTE

AI를 쓴 만큼 짧게 적습니다. 사용량은 평가 기준이 아니고, 설명할 수 없는 코드·검토 없는 제출·출처 미기재가 감점입니다. 각 시나리오 끝에 채운 예시가 있습니다. 근거가 필요하면 /export로 대화를 파일로 내보내고 /usage 화면을 캡처해 둡니다.

AI USE NOTE
- 어떤 도구: Claude Code (Manual 모드)
- 어떤 작업을 맡겼나:
- 무엇을 판단했나: (허락한 것 · 거절한 것 · 범위를 바꾼 것)
- 어떻게 검증했나: (/diff · 테스트 출력 · 브라우저 확인)

PR 본문에는 한 줄로 줄입니다. AI USE NOTE: 도구 / 맡긴 작업 / 판단 / 검증. 양식 파일은 교안 저장소의 templates/AI-USE-NOTE.md에 있습니다.

설치, 로그인, 시작과 종료

명령은 공식 문서 원문입니다. 계정이 없으면 읽기만 하고 04로 넘어가도 됩니다.

설치

공식 권장은 네이티브 설치입니다. npm으로도 되지만 Node.js 22 이상이 필요하고, sudo npm install -g는 쓰지 않습니다(원문: "Do NOT use sudo npm install -g as this can lead to permission issues and security risks."). 설치 중에는 진행 표시가 없다가 끝나면 "Claude Code successfully installed!"가 뜹니다.

$ curl -fsSL https://claude.ai/install.sh | bash
$ claude --version
2.1.211 (Claude Code)

Homebrew를 쓴다면 brew install --cask claude-code도 됩니다(자동 업데이트 없음, brew upgrade claude-code).

irm https://claude.ai/install.ps1 | iex
claude --version

WinGet은 winget install Anthropic.ClaudeCode. Git for Windows를 함께 설치해 두면 Bash 도구를 쓸 수 있습니다. 없으면 PowerShell 도구로 동작합니다.

$ node -v
v24.11.0
$ npm install -g @anthropic-ai/claude-code
$ claude --version

업그레이드는 npm install -g @anthropic-ai/claude-code@latest입니다. 문서는 npm update -g를 피하라고 적습니다.

확인과 관리 명령 세 가지입니다. claude --version은 버전, claude doctor는 설치·설정 진단(세션을 시작하지 않음), claude update는 수동 업데이트입니다. 시스템 요건은 macOS 13+, Windows 10 1809+, Ubuntu 20.04+, RAM 4GB 이상, 인터넷 연결입니다.

command not found: claude

설치는 되었는데 PATH에 없는 경우입니다. zsh라면 echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc. Windows에서는 'claude' is not recognized로 나오고, 터미널을 새로 열면 해결되는 때가 많습니다.

로그인

  1. 프로젝트 폴더에서 claude첫 실행이면 브라우저 창이 열려 로그인을 요청합니다. 홈 폴더가 아니라 저장소 폴더에서 시작합니다.
  2. 계정 유형 고르기원문 순서: "Claude Pro, Max, Team, or Enterprise (recommended)" / "Claude Console (API access with pre-paid credits)" / 기업용 클라우드. 학생은 첫 번째 또는 두 번째입니다.
  3. 브라우저가 안 열리면c를 눌러 로그인 URL을 복사합니다. 브라우저가 코드를 보여 주면 터미널의 "Paste code here if prompted"에 붙여 넣습니다.
  4. "Login successful"Enter로 계속합니다. 자격 증명은 저장되어 다음부터 묻지 않습니다. 계정 전환은 /login, 로그아웃은 /logout, 셸에서 상태 확인은 claude auth status.

환경 변수 ANTHROPIC_API_KEY가 설정되어 있으면 로그인 창을 건너뛰고 구독이 아니라 API로 과금됩니다. 실습용으로 키를 넣어 둔 적이 있다면 지웁니다. 키는 어디에도 커밋하지 않습니다.

시작 화면과 종료

프롬프트 위에 버전, 현재 모델, 작업 디렉터리가 보입니다. 처음 여는 폴더면 작업 폴더를 신뢰할지 묻는 대화상자가 먼저 뜹니다. 그 폴더의 설정이 부여하는 허용 규칙과 추가 디렉터리를 나열하니 읽고 수락합니다. 홈 디렉터리에서 시작하면 신뢰가 저장되지 않아 매번 다시 묻습니다. CLAUDE.md가 없고 AGENTS.md가 있으면 no CLAUDE.md found; AGENTS.md loaded: … 같은 줄이 보입니다.

$ cd team-notes
$ claude                         # 대화형 세션
$ claude "fix the build error"   # 첫 요청을 함께
$ claude -c                      # 가장 최근 대화 이어가기
$ claude -r                      # 세션 골라서 이어가기
$ claude --permission-mode plan  # Plan 모드로 시작 (04)
$ claude -p "explain this function"   # 한 번 답하고 종료

처음 물어볼 문장은 공식 문서의 예시를 그대로 써도 됩니다. what does this project do?, explain the folder structure, what technologies does this project use?. 한국어로 물어도 됩니다. 종료는 /exit, 또는 빈 프롬프트에서 Ctrl D 두 번입니다.

화면 읽기: 권한 모드, 권한 요청, Plan, diff와 되돌리기

연습 화면을 열기 전에 상태 표시줄과 권한 요청의 문구를 익혀 둡니다. 영어 문구는 공식 문서의 원문이고, 괄호 안은 뜻입니다.

상태 표시줄의 권한 모드

프롬프트 아래 상태 표시줄에 지금의 권한 모드가 보입니다. Shift Tab으로 바꿉니다. 최근 버전(v2.1.283 이후)은 터미널에서 auto 모드로 시작합니다. 분류기가 사람 대신 승인하는 모드입니다. 수업에서는 처음에 Shift Tab을 한 번 눌러 ⏸ manual mode on을 확인하고 시작합니다. 문서 원문도 같은 주의를 줍니다. "Auto mode reduces permission prompts but does not guarantee safety."

권한 요청 읽기

Manual 모드에서 명령을 실행하려 할 때 뜨는 요청입니다. 문구는 공식 문서가 설명하는 Bash 요청 그대로이고, 배치는 연습 화면용으로 다시 그린 것입니다.

Bash command
  Run the test suite
    npm test
  This command requires approval

  Do you want to proceed?
  ❯ 1. Yes
    2. Yes, and don't ask again for: npm test *
    3. Yes, and switch to auto mode
    4. No
  Esc to cancel · Tab to amend
Yes
이번 한 번만 허락합니다. 처음에는 늘 이것입니다. 위의 설명("Run the test suite")과 실제 명령(npm test)이 맞는지 읽습니다.
Yes, and don't ask again for: …
이 명령 패턴을 허용 목록에 저장합니다. 저장소 루트의 .claude/settings.local.json에 "Bash(npm test *)"로 들어가 다음 세션에도 적용됩니다. npm test처럼 안전하다고 직접 확인한 명령에만 씁니다. 파일 수정 허락은 저장되지 않고 세션이 끝날 때까지만 유지됩니다.
Yes, and switch to auto mode
이후 요청을 분류기에 맡깁니다. 수업에서는 고르지 않습니다. 사람이 확인하는 지점이 사라집니다.
No · Esc
거절합니다. Tab을 누르면 답에 한 줄 이유를 붙일 수 있고(Tab to amend), 이유가 전달되면 에이전트가 다른 방법으로 계속합니다. 이유 없이 No면 멈춥니다.

묻지 않는 것도 있습니다. ls, cat, pwd, grep, find, git status, git log, git diff 같은 읽기 전용 명령은 어느 모드에서도 묻지 않습니다. 반대로 curl, wget 같은 네트워크 명령은 자동 승인되지 않습니다.

허용·거절 규칙

/permissions에서 allow·ask·deny 규칙을 보고 고칩니다. 규칙은 deny → ask → allow 순서로 읽히고 처음 맞는 것이 결정합니다. 원문: "An allow rule can't carve an exception out of a deny rule." 팀 저장소에 두고 커밋하는 공용 설정은 .claude/settings.json, 나만의 것은 .claude/settings.local.json(자동으로 git 제외)입니다. 파일은 주석 없는 엄격한 JSON입니다.

{
  "permissions": {
    "allow": [
      "Bash(npm run lint)",
      "Bash(npm run test *)",
      "Bash(git commit *)"
    ],
    "deny": [
      "Bash(git push *)",
      "Read(./.env)",
      "Read(./.env.*)"
    ]
  }
}

규칙 문법은 Tool 또는 Tool(명령)입니다. Bash(npm run build)는 정확히 그 명령, Bash(npm run *)는 npm run … 계열입니다. &&, ;, |로 이어진 복합 명령은 각 부분이 모두 맞아야 허용됩니다. 아래 실습에서 그 규칙을 코드로 확인합니다. 복합 명령 처리가 빠져 있어 테스트 두 개가 실패합니다. 명령을 나누어 각 부분을 판정하도록 decide를 고치세요.

힌트: cmd.split(/\s*(?:&&|;|\|)\s*/)로 나눈 뒤 decideOne을 각각 적용합니다. 실제 도구에서도 deny 규칙은 명령 문자열만 보므로 sh -c '…' 같은 우회는 못 막습니다. 꼭 막아야 하는 것은 훅으로 합니다(07 심화).

Plan 모드: 바꾸기 전에 계획만

원문: "Plan mode tells Claude to research and propose changes without making them. Claude reads files, runs shell commands to explore, and writes a plan, but does not edit your source." Shift Tab으로 ⏸ plan mode on까지 가거나, 한 요청만 /plan 요청 내용으로 보냅니다. 계획이 나오면 승인 요청이 뜹니다. 선택지 원문은 다음과 같습니다.

  • Yes, and use auto mode (auto가 안 되는 환경에서는 Yes, auto-accept edits)
  • Yes, manually approve edits: 수업에서는 이것입니다. 파일마다 다시 묻습니다
  • No, keep planning: 계획을 더 다듬습니다. Ctrl G로 계획 글을 편집기에서 직접 고칠 수도 있습니다

모범 사례 문서의 순서는 Explore → Plan → Implement → Commit입니다. 다만 "If you could describe the diff in one sentence, skip the plan." 한 줄로 설명되는 변경은 바로 요청합니다.

diff 보기와 되돌리기

변경은 세 곳에서 봅니다. 권한 요청 안의 diff(허락 전), /diff(세션에서 바뀐 파일 목록과 파일별 diff, 턴별 보기), 그리고 터미널의 git diff(커밋 전 최종 확인)입니다. 되돌리기는 세 단계입니다.

  1. 체크포인트 /rewind빈 입력에서 Esc Esc를 눌러도 됩니다. 요청을 보낼 때마다 자동으로 저장된 스냅샷으로 돌아갑니다.
  2. 에이전트에게 요청"방금 바꾼 것을 되돌려 줘"처럼 말로 합니다. 이것도 편집이므로 diff를 다시 읽습니다.
  3. git영구 기록은 git입니다. 작업 전에 커밋해 두고, 문제면 git restore 파일로 돌립니다. 원문: "Not a replacement for version control."

내부 동작
권한 규칙은 모델이 아니라 Claude Code라는 프로그램이 강제합니다. 원문: "Permission rules are enforced by Claude Code, not by the model. Instructions in your prompt or CLAUDE.md shape what Claude tries to do, but they don't change what Claude Code allows." 그래서 "git push 하지 마"를 CLAUDE.md에 적는 것과 "deny": ["Bash(git push *)"]를 설정에 적는 것은 다른 층입니다. 앞은 부탁, 뒤는 벽입니다. 다만 deny 규칙은 명령 문자열만 보므로 /bin/rm이나 sh -c '…'로 감싼 명령은 못 잡습니다. 진짜 경계가 필요하면 훅(PreToolUse, 07 심화)이나 샌드박스를 씁니다.

Permissions · Permission modes · Settings
트레이드오프
허용 목록을 넓히면(Bash(npm run *)) 요청이 줄어 편하지만, package.json의 scripts가 바뀌면 그 패턴이 뜻하는 명령도 바뀝니다. 명령 단위로 좁게 적을수록 안전하고 번거롭습니다. 수업 저장소에서는 npm test, npm run lint처럼 결과를 읽기만 하는 명령만 허용하고 나머지는 묻게 둡니다.

두 도구를 함께 쓰는 팀은 AGENTS.md 하나를 진실 원천으로 두고 CLAUDE.md 첫 줄에 @AGENTS.md만 적어도 됩니다. Claude Code는 CLAUDE.md가 없으면 AGENTS.md를 대신 읽고(v2.1.277 이후), Codex는 AGENTS.md를 읽습니다. 템플릿은 교안 저장소의 templates/AGENTS.md와 templates/docs/에 있습니다.

안전 수칙

공식 보안 문서의 다섯 가지(원문)와 수업의 금지선입니다. "1. Review suggested commands before approval 2. Avoid piping untrusted content directly to Claude 3. Verify proposed changes to critical files 4. Use virtual machines (VMs) to run scripts and make tool calls, especially when interacting with external web services 5. Report suspicious behavior with /feedback".

  • 권한 요청을 읽고 답합니다. "Yes, and don't ask again"은 npm test처럼 안전하다고 확인한 명령에만.
  • 남이 쓴 Issue·README·웹 페이지를 에이전트가 읽을 때는 그 안에 지시문이 섞여 있을 수 있습니다(프롬프트 인젝션). curl·wget은 자동 승인되지 않고, 가져온 내용은 요약 모델을 거칩니다. 그래도 이상한 행동이 보이면 Esc.

  • --dangerously-skip-permissions는 쓰지 않습니다. 원문: "Only use this mode in isolated environments like containers, VMs, or dev containers without internet access, where Claude Code cannot damage your host system." 그리고 "bypassPermissions offers no protection against prompt injection or unintended actions." 이 플래그는 사람이 확인하는 지점을 전부 없앱니다. 수업 노트북에서는 쓰지 않습니다.

홈 폴더에서 claude를 실행한다
